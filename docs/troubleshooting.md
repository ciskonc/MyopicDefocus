## 零、先做这三步

绝大多数问题在做完这三步之前都别去改配置：

| 步骤 | 怎么做 | 为什么 |
|------|--------|--------|
| **1. 确认程序在跑** | 任务栏右下角（可能要点 `^` 展开隐藏区）能看到托盘图标 | 没图标 = 程序没启动，后面全是白查 |
| **2. 确认没被暂停** | 右键托盘图标，看菜单第一项是「暂停效果」还是「恢复效果」 | 菜单写「暂停效果」= 当前**正在生效**；写「恢复效果」= 已被暂停 |
| **3. 确认参数填对** | 打开设置面板，核对「屏幕对角线」「观看距离」两个数 | 90% 的「没效果」是这两个物理量填错 |

**仍然不行再看下面的对应条目。**

## 二、逐条排查

### 2.1 画面全黑或全蓝

**现象**：整个屏幕被一层黑色或纯蓝色盖住，下面的窗口看不见。

**可能原因**

| 原因 | 说明 |
|------|------|
| **抓屏失败** | 程序从屏幕抓画面失败，纹理里没有有效数据，于是把一块黑/蓝推到了最上层 |
| 全屏独占游戏 | 独占模式下画面不进桌面合成器，DXGI 抓不到 |
| 显卡驱动异常 | 抓屏接口返回失败后没能恢复 |

**怎么排查**

1. 看看是不是在**全屏独占游戏**里 —— 是的话按 [2.9](#29-独占全屏的游戏里没有效果) 处理；
2. 按 `Ctrl + Alt + Q` 退出程序，看屏幕是否恢复正常 —— 恢复了说明确实是这层滤镜盖上去的；
3. 重启电脑后**先不运行程序**，直接用几分钟看看是否正常 —— 排除系统级/驱动级问题；
4. 换接 HDMI / DP 线（而不是 HDMI 转接器或扩展坞），扩展坞常导致抓屏失败。

**怎么解决**

- 全屏独占游戏 → 在游戏图形设置里改成「**无边框窗口**」或「**窗口化**」；
- 抓屏确实失败 → 重启程序；仍不行就换线/换接口；
- 排查进度用 `Ctrl + Alt + Q` 随时关掉这层滤镜。

---

#### 自查：把当前帧导出来看

程序内置了取证模式，会把「抓到的桌面原图」和「叠加效果后的输出」各存一张 BMP：

```powershell
MyopicDefocus.exe --capture="C:\Users\你的用户名\Desktop\mdcap"
```

生成两个文件：

- `*_captured.bmp` —— DXGI 抓到的桌面**原图**
- `*_rendered.bmp` —— 叠加离焦效果后的**输出**

按这个表判读：

| captured | rendered | 说明 |
|---|---|---|
| 有画面 | 全黑 | 渲染管线问题（着色器资源绑定 / 常量缓冲），不是抓屏问题 |
| 全黑 | 全黑 | 抓屏失败，往上查独占全屏、驱动、显示模式 |
| 有画面 | 有画面，边缘发糊、能看到彩色镶边 | 正常 |
| 有画面 | 与原图完全一样 | 效果强度为 0，或参数算出的模糊半径过小 |

> 取证模式只支持 8 位 BGRA 源格式。10bit 屏上若提示「源格式不是 8bit BGRA」，说明抓屏源是 10bit，属于正常降级路径，不影响实际使用。


### 2.17 画面无限叠加、画面互相重叠，最后整机卡死

**现象**：画面上的窗口像复印一样一层层叠上去，窗口轮廓逐渐溶解成彩色重影，最后画面全糊、鼠标键盘都失灵，只能强制重启。

**这是最严重的一种故障**，但它有明确的成因和确定的解法。

#### 成因：滤镜窗口把自己抓进了自己的画面里

程序用 DXGI「桌面复制」抓取屏幕，再把抓到的画面渲染回一个覆盖全屏的滤镜窗口。这个滤镜窗口本身也在屏幕上，于是下一帧抓到的画面里**已经包含了上一帧的滤镜窗口**。每一帧都在给上一帧再糊一次，画面就以几何级数劣化，最终 GPU 打满、整机卡死。

实测数据（同一份程序，抓第 1 帧与第 200 帧比较清晰度）：

| 状态 | 第 1 帧 | 第 200 帧 | 结论 |
|---|---|---|---|
| 「对截图和录屏隐藏」开启 | 3226.69 | 3226.72 | **完全稳定，零递归** |
| 「对截图和录屏隐藏」关闭 | 3226.72 | **106.70** | **1 秒内劣化 97%** |

#### 解法

1. **保持「对截图和录屏隐藏」为开启状态**。它不只是隐私开关，更是防止这个递归的开关——开启时滤镜窗口不进入捕获流，递归从根上消失。
2. **程序已内置三道保险**：
   - 启动时若发现该开关是关闭的，**强制改回开启**并提示；
   - 运行时每 30 帧测一次画面清晰度，**连续 3 次大幅下降即判定为递归，自动恢复该开关**；
   - 在设置面板里手动关闭时，会先弹出警告说明会导致卡死。
3. 如果已经卡死：按 `Ctrl+Alt+Shift+End` 或用任务管理器结束 `MyopicDefocus.exe`，不需要重启整机。

> **为什么这个开关关不掉？** 这是全屏滤镜的物理限制，不是程序缺陷。要让滤镜窗口在截图里可见，它就必须进入捕获流，也就必然被自己抓到。除非改用完全不同的技术路线（逐窗口合成），否则「关闭」只能作为临时开关，且随时会被自动恢复。



### 2.18 右下角没有托盘图标（程序能跑、效果正常，但图标不出现）

**现象**：滤镜效果正常工作，设置面板能打开，但任务栏右下角通知区里找不到程序图标，右键菜单也点不到。

**根因：exe 所在目录带「低完整性级别」强制标签。**

`Mandatory Label\Low Mandatory Level` 是 Windows 给可被任意用户执行的文件加的标记，位于某些开发工作区（如自动化工作目录）下会被自动加上。它的影响链是：

1. 微软明确规定：新进程的完整性级别 = **min(用户令牌的 IL, 文件的 IL 标签)**。
   → 即使你以管理员身份运行，只要文件带 Low 标签，`min(High, Low) = Low`，**提权完全无效**。
2. 托盘图标由 `explorer.exe`（Medium IL）承载，`Shell_NotifyIcon` 内部靠向任务栏窗口发送消息实现。
3. Low IL 进程向 Medium IL 进程发消息会被 **UIPI** 拦截，发送方 `GetLastError()` 得到 **5 (ERROR_ACCESS_DENIED)**。
4. 于是 `Shell_NotifyIcon` 恒返回 FALSE，托盘图标建不出来。

**本机实测对照**（同一份二进制，只换运行位置）：

| 运行位置 | 文件标签 | 进程 IL | 托盘 |
|---|---|---|---|
| 开发工作区内 | Low (NW) | Low | **失败 err=5** |
| 桌面 / `%LOCALAPPDATA%\Temp\` | 无 | Medium | **成功** |
| 工作区内执行 `icacls /setintegritylevel M` 后 | Medium | Medium | **成功** |

**解决办法（任选其一）**：

1. **把 exe 复制到没有 Low 标签的目录再运行**，例如桌面或 `%LOCALAPPDATA%\MyopicDefocus\`。这是最省事、也最推荐的做法。
2. 以管理员身份执行一次 `icacls "完整路径\MyopicDefocus.exe" /setintegritylevel M`，永久去掉文件的 Low 标签（需要管理员权限）。
3. 不处理也行 —— 程序会自动降级为**右下角自绘小图标 + 菜单**，并注册 `Ctrl+Alt+S/P/Q` 全局热键，功能不受影响。

**如何确认自己是不是这个问题**：运行随附的诊断程序，它会直接告诉你「托盘是否可用」；也可以执行
`icacls "你的exe路径"`，若输出里出现 `Mandatory Label\Low Mandatory Level` 就是它。

> 顺带说明：`Shell_NotifyIcon` 在 Win11 24H2 仍是**唯一受支持**的建托盘方式。传闻中的 `ITrayNotifyWin10`（CLSID `{25DEEA4A-…}`）在本机根本不存在（`0x80040154`）；真正存在的是 `CLSID_TrayNotify {25DEAD04-…}` + `ITrayNotifyWin8`，但它**只有**「调整已存在图标的显示偏好」这类方法，**不能创建图标**，无法替代。通知区图标在架构上就是 explorer.exe 画的按钮，没有任何受支持 API 能在 explorer 缺席时塞图标进去。



### 2.19 托盘图标建起来了却看不见（被收进 ^ 溢出区）

**现象**：日志显示托盘创建成功，但任务栏右下角找不到图标，得点「^」隐藏图标的小箭头才看得到。

**这是 Windows 11 的默认行为**：第三方应用的托盘图标默认折叠进溢出区，只有用户手动把它拖出来或设置「始终显示」才会常驻。

**解决办法（需手动设置一次）**：右键托盘区的 `^` 箭头 → 在弹出的列表里找到本程序 → 右键 → 选「**始终显示**」。这是系统自己的偏好设置，应用无法代劳。

> **本项目曾尝试用未公开接口自动完成这一步，但已放弃。**
> shell 内部接口 `ITrayNotifyWin8::SetPreference(PREFERENCE_SHOW_ALWAYS)` 确实存在且本机可创建，
> 但它要求跨进程 COM 调用（explorer 里的对象），而 MinGW/libc++ 下缺少正确的 marshaling：
> explorer 一发通知回调就会打到进程里，导致 **RPCRT4.dll 访问违例（0xc0000005）崩溃**。
> 未公开 API + 不安全的 ABI 组合，风险大于收益，故整体移除该代码路径。
> 现在托盘图标创建稳定（实测 90 秒无崩溃），只是默认会被 Win11 折叠，需要手动设一次。

### 2.20 面板文字压在按钮上 / 字体发虚

**现象**：设置面板里的静态文字（如「屏幕 1: \.\DISPLAY1（使用通用设置）」）显示不全，像是压到了右边的按钮上；字体看起来是宋体而不是系统 UI 字体。

**根因**：Win32 控件默认使用 GDI 的 "System" 字体，中文环境下是**宋体 12pt**，字号比现代 UI 字体大，静态文本会撑出预设的控件宽度。控件布局本身（标签 14~264 / 按钮 272~408）并没有重叠。

**已修**：程序在面板建好后统一给所有子控件设置 `DEFAULT_GUI_FONT`（Segoe UI / 微软雅黑 9pt），并给标题加上 `SS_ENDELLIPSIS`（过长时显示省略号而不是溢出）。



### 2.21 「恢复效果」按了没反应（手动恢复被自动暂停压回）

**现象**：程序检测到全屏游戏自动暂停了效果，此时你按 `Ctrl+Alt+P` 或托盘菜单的「恢复效果」，画面上的滤镜没有回来（或闪一下又消失）。

**根因**：手动恢复和自动暂停在打架——你刚把效果恢复，主循环下一帧检测到抓屏仍是失败状态（游戏还在运行），自动暂停逻辑立刻又把滤镜层隐藏了。手动操作被自动逻辑覆盖。

**已修**：手动恢复永远优先。你在降级期间手动恢复了效果，程序会记住这个选择，**本次降级周期内不再自动暂停**；等抓屏恢复健康（比如游戏退出）后，自动暂停能力自动恢复。

**如果你在游戏还在运行时强行恢复了效果**：效果处于「启用」状态，但滤镜层**不会显示**——因为抓不到新画面，显示旧帧只会让画面冻结。一旦切回桌面（抓屏恢复），滤镜会**自动出现**，无需再操作。



### 2.22 对角线探测失败（使用默认 24 英寸）

**现象**：日志出现 `diagonal probe unavailable - keeping xx inch`。

**说明**：程序从显示器 EDID（注册表）自动探测物理对角线；探测失败时**保留配置里已有的值**（不再用 24 英寸覆盖，v1.8.6 起）。探测成功时会自动更新。常见于：虚拟显示器、远程桌面会话、或注册表读取被安全软件拦截。

**影响**：对角线差 1~2 英寸只会让模糊半径有轻微偏差，视觉差异很小。确有需要可在配置文件里手动设 `diagInch` 字段（单位英寸），程序仍会尊重该值。


### 2.23 配置文件出现 `.encoding-bak` 是什么

**现象**：`%APPDATA%\MyopicDefocus\` 下多出一个 `config.json.encoding-bak` 文件，当前 config.json 里的参数和之前不一样。

**说明**：config.json 被编辑器以**非 UTF-8 编码**（最常见：记事本「另存为」选了 UTF-16 或 ANSI）保存过后，程序读不出内容，只能按默认值运行。为防止你手调的参数被默认值覆盖，程序会：

1. 把那份无法读取的原文件**原样备份**为 `config.json.encoding-bak`；
2. 之后才会写入新配置。

**怎么恢复手调参数**：用记事本打开 `.encoding-bak` 文件 → 「另存为」→ 编码选 **UTF-8** → 文件名改回 `config.json`（覆盖当前文件）→ 重启程序。参数即恢复。

**已知限制**：exe 所在目录带「低完整性级别」标签（如某些受管控的工作区）时，Low 完整性进程无权写入 `%APPDATA%`，备份文件不会生成——此时请从回收站/编辑器的本地历史找回原文件，或将 exe 移到普通目录（桌面、`%LOCALAPPDATA%`）再运行。


### 2.2 屏幕偏色或过曝

**现象**：开着滤镜后颜色明显不对 —— 偏蓝、偏黄、过曝、暗部发灰；关掉滤镜就正常。

**可能原因**：**系统 HDR 开着。**

这是本软件**明确不支持**的场景：抓屏拿到的是 HDR 源，但滤镜的处理管线工作在普通 SDR 空间，两边的色调映射对不上，结果就是颜色失真。

**怎么排查**

1. 打开 **设置 → 系统 → 显示 → HDR**（或「显示设置 → HDR」）；
2. 看开关是不是打开的；
3. 也顺便确认一下显示器自己的 OSD 菜单里有没有开 HDR / HDR10 模式。

**怎么解决**

**关掉系统 HDR**（也建议关掉显示器 OSD 里的 HDR 开关），然后重启滤镜程序。

> 本软件**不做 HDR 适配**。这是有意为之的设计取舍，不是待修的 bug。

**附加风险（D7，读码确认）**：HDR 抓屏格式（非 8bit）下，递归自愈看门狗的清晰度采样**没有数据**（采样函数对非 `B8G8R8A8_UNORM` 直接放弃）——即 HDR 下"画面自我叠加"的自动防护第三道保险失效。因此 HDR 环境如出现画面异常叠加，请立即 `Ctrl+Alt+Q` 退出，不要等待自动恢复。

### 2.3 只有左上角一小块有画面

**现象**：滤镜只覆盖了屏幕左上角的一小块，其余区域没有效果。

**可能原因**：**DPI 缩放没被正确处理**。Windows 在 125% / 150% / 175% 缩放下，逻辑像素和物理像素不是 1:1；如果进程没有声明「per-monitor DPI 感知」，抓屏和窗口坐标就会错位。

**怎么排查**

1. 右键 exe → **属性** → **兼容性** → **更改高 DPI 设置**；
2. 看「**替代高 DPI 缩放行为**」是不是选了「应用程序」；
3. 确认 Windows 显示设置里的**缩放**是多少（125%？150%？）；
4. 确认应用自己声明了 per-monitor v2 DPI 感知（源码里必须有 `SetProcessDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE_V2)` 这一句）。

**怎么解决**

- 如果 exe 属性里的 DPI 设置被改坏了 → 改回「**应用程序**」或「**无**」，重新启动程序；
- 缩放级别本身**不影响**效果大小（效果大小只跟物理尺寸、观看距离有关），所以**不要为了这个去调缩放**；
- 若确认程序内已调用 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` 仍有问题 → 把「显示缩放 = 100%」和「缩放 = 100%」作为对照测试一次，能定位是否是缩放链路的问题。

### 2.4 10bit 屏幕输出仍然是 8bit

**现象**：显示器是 10bit / HDR 屏，但滤镜输出看起来还是 8bit，色彩层次不够。

**可能原因**：**Windows 抓屏接口只提供了 8bit 的桌面副本**。系统的桌面合成输出格式决定了抓到的是什么颜色深度，软件这边没法凭空变出 10bit。

**怎么排查**

1. 确认显示器确实工作在 10bit 模式（显示器 OSD 里设置）；
2. 确认 Windows 显示设置里该显示器的**色深**是 8bit 还是更高；
3. 了解一个事实：**抓屏拿到什么深度，滤镜就按什么深度输出**——这是设计上的自动跟随。

**怎么解决**

**这是正常现象，不需要处理。** 程序会**自动跟随**抓屏源的色深做降级，不会有任何报错或提示。

如果一定要 10bit，需要在 Windows 侧把桌面输出格式切到 10bit（前提是你的显卡和显示驱动支持），而不是在软件里找开关。

### 2.5 画面完全没有模糊效果

**现象**：滤镜确实在跑（托盘图标在、菜单显示「暂停效果」），但画面看起来和没开一样。

**可能原因**

| 原因 | 判断方法 |
|------|---------|
| **观看距离填得太大** | 距离越大算出的模糊越少；填成 100+ cm 时基本看不出来 |
| **屏幕对角线填得太大** | 对角线填大 → 每像素代表的毫米数变大 → 换算成像素的模糊量变小 |
| **效果强度太低** | 强度低时模糊版占比小，和原图几乎一样 |
| 算出来的 σ ≈ 0 | 极端参数（例如观看距离填成 5 cm 以下）会让模糊量趋近 0 |

**怎么排查**

1. 打开设置面板，**先确认两个物理量**：
   - 「屏幕对角线」是不是等于你实际量出来的英寸数；
   - 「观看距离」是不是接近你眼睛到屏幕的真实距离；
2. 把「效果强度」**临时拉到 0.8~1.0**，看画面有没有变化：
   - **有变化** → 参数链路是通的，问题在数值上，回到第 1 步细调；
   - **完全没变化** → 不是参数问题，往下看。
3. 检查是不是**被暂停了**：右键托盘图标，菜单第一项应该是「暂停效果」四个字。

**怎么解决**

- 对角线 / 距离填错 → 重新量、重新填；
- 强度太低 → 从 0.25 往上调；
- 试到 1.0 都完全没反应 → 重启程序；仍无效请按 [2.1](#21-画面全黑或全蓝) 排查抓屏是否正常。

### 2.6 效果太弱或太强

**现象**：能看出效果，但和预期不符。

**可能原因**：效果强度滑块的位置；以及观看距离、对角线这两个物理量与真实值不符。

**怎么排查**

| 你的感受 | 大概率原因 | 调整方向 |
|---------|-----------|---------|
| 太弱、几乎无感 | 强度低 / 距离填太大 / 对角线填太大 | 强度 ↑；距离和对角线改成真实值 |
| 太强、字发糊、彩边夸张 | 强度高 / 距离填太小 / 对角线填太小 | 强度 ↓；距离和对角线改成真实值 |

**怎么解决**

1. **先把物理量改对**（这是根因）；
2. 再用「效果强度」做最后微调；
3. 建议日常区间 **0.15 ~ 0.4**，默认 0.25；
4. 强度 1.0 = 完全用模糊版，几乎无法正常看字，**不要长期开**。

### 2.7 杀毒软件报「DLL 注入」或木马

**现象**：Windows Defender 或第三方杀软在启动时报警，提示「检测到 DLL 注入」「可疑行为」「远程线程创建」等。

**可能原因**：**DXGI 抓屏 API 的常见误报。**

程序的抓屏能力来自 `IDXGIOutputDuplication`（DXGI Desktop Duplication），这一类 API 在安全软件的行为特征库里和「远程代码注入」「截屏窃取」高度重合，容易触发规则。

**怎么排查**

1. 看告警里的**具体特征描述**；
2. 用**文本编辑器打开 exe**，在二进制里搜 `http`、`https`、`socket`、`WinHttp`、`WinInet` —— **一条都搜不到**，就说明程序里没有任何联网代码；
3. 用杀软自带的「**查看文件属性 / 查看文件来源**」确认文件来源可信。

**怎么解决**

- 确认程序**不含任何网络/外发代码**（上面第 2 步能验证），属于误报；
- 把 exe 或所在目录加入杀软白名单；
- 建议从**源码自行编译**一份，这样杀软对未签名的自编译程序的误报率也更低。

### 2.8 AMD 显卡上黑屏

**现象**：在 AMD 显卡的机器上，滤镜层全黑或显示异常；Intel / NVIDIA 显卡上正常。

**可能原因**：**分层窗口（WS_EX_LAYERED）与 FLIP 交换链不兼容。**

滤镜的输出窗口是 Win32 分层窗口，而 DirectX 的 FLIP 模型交换链和分层窗口组合时，合成器无法正确合成，在部分 AMD 驱动上直接黑屏。

**怎么排查**

1. 确认显卡确实是 AMD；
2. 确认驱动是较新的版本；
3. 确认当前用的是**「BitBlt / DISCARD 模型」交换链**而不是 FLIP 模型（源码里 `DXGI_SWAP_CHAIN_DESC1::SwapEffect` 应为 `DXGI_SWAP_EFFECT_DISCARD`）—— **本项目已经改用 DISCARD(BitBlt) 交换链来规避这个问题**。

**怎么解决**

- 确认用的是 DISCARD 模型（上游 v3.1 版本就是修了这个问题的版本，release 说明里写的是「修复 AMD 平台…」）；
- 仍然黑屏 → 更新 AMD 驱动；再不行请提 issue，并附上：显卡型号、驱动版本、Windows 版本。

### 2.9 独占全屏的游戏里没有效果

**现象**：在游戏里看不到滤镜效果，但切回桌面又有了。

**可能原因**：**DirectX「独占全屏」模式下，画面不经过桌面合成器**，DXGI Desktop Duplication 抓不到任何内容。这不是软件缺陷，是 Windows 显示栈的机制限制。

程序会**自动暂停**并**在托盘给出提示**，不会崩溃、不会反复刷屏。

**怎么排查**

1. 在游戏的图形设置里找到显示模式选项；
2. 确认它当前是不是「独占全屏 / 全屏」；
3. 确认切到「**无边框窗口**」或「**窗口化**」后效果是否恢复。

**怎么解决**

- 把游戏改成**无边框窗口 / 窗口化**模式；
- 效果会在游戏切回无边框时自动恢复。

### 2.10 托盘图标不见了

**现象**：找不到程序图标。

**可能原因**

| 原因 | 判断 |
|------|------|

| 程序已经退出 | 按 `Ctrl + Alt + Q`（如果程序在跑，会直接退出；如果没反应，说明已经退出了） |

**怎么排查**

2. 打开**任务管理器 → 详细信息**，看有没有 `MyopicDefocus.exe` 进程；
3. 有进程但没图标 → 托盘图标创建失败，重启程序。

**怎么解决**

- 重新双击 exe 启动；
- 启动后立刻右键图标 → **开机自启**打开，以后开机自动在。

### 2.11 第一次运行没有弹出设置向导

**现象**：双击 exe 后直接进入托盘常驻，没有向导窗口。

**可能原因**

| 原因 | 说明 |
|------|------|
| 已经有配置文件了 | `%APPDATA%\MyopicDefocus\config.json` 存在时不会再向导 |
| 之前用过旧版并被回退读取 | 旧版 `config.json` 存在时，会**直接沿用旧配置**，不再向导 |
| 想重来一次 | 需要先清掉配置 |

**怎么排查**

1. 打开 `%APPDATA%\MyopicDefocus\`，看 `config.json` 在不在；
2. 再看看 exe 同目录有没有旧版 `config.json`。

**怎么解决**

- 想重新填一遍 → 退出程序 → 删掉 `%APPDATA%\MyopicDefocus\config.json` → 重新双击 exe；
- 也可以不进向导，直接**右键托盘图标 → 打开设置面板**，在面板里改同样的三项参数。

### 2.12 两块显示器的参数互相干扰

**现象**：给副屏单独调了参数，主屏也跟着变了。

**可能原因**：面板当前处于「**一套通用参数**」模式 —— 这个模式下所有屏幕共用同一组参数，改哪儿都一起变。

**怎么排查**

1. 打开设置面板，看上半部分的模式选择；
2. 是不是停在「一套通用参数」上；
3. 有多块屏时，「单独改这块屏」模式里会有一个**显示器选择框**，确认你选的是目标屏。

**怎么解决**

1. 切到「**单独改这块屏**」；
2. 在显示器列表里选中要调的那块；
3. 调完参数，这块屏独立生效，其他屏不受影响。

> 补充：每块屏会**各自按自己的刷新率**运行（120 Hz 的屏 120 fps，60 Hz 的屏 60 fps），不需要也不能手动指定帧率。

### 2.13 截图和录屏里看不到滤镜效果

**现象**：自己屏幕上明明有滤镜效果，但截图/录屏里是原始画面。

**可能原因**：**「对截图和录屏隐藏」默认是打开的**（这是有意设计的防录屏特性）。

**怎么排查**

1. 打开设置面板，找「**对截图和录屏隐藏**」复选框；
2. 确认它是不是勾选状态。

**怎么解决**

- 想让截图/录屏**带上**滤镜效果 → 取消勾选这个选项；
- 想恢复默认（不让滤镜出现在录屏里） → 重新勾上。

> 这个开关**只**影响「滤镜层是否出现在抓屏结果里」，不影响滤镜本身在你屏幕上的显示，也不影响其他程序（Word、游戏等）能不能被正常截图。

### 2.14 开机没有自动启动

**现象**：重启电脑后程序没有自己起来。

**可能原因**

| 原因 | 说明 |
|------|------|
| 「开机自启」没开 | 默认是**关**的 |
| 被安全软件/清理工具拦了 | 开机启动项常被优化工具默认禁用 |
| exe 位置变了 | 换过目录后启动项指向旧路径就失效了 |

**怎么排查**

1. 右键托盘图标 → 看「开机自启」是不是勾着的；
2. 打开**任务管理器 → 启动应用**（或 `Win + R` → `shell:startup`），看列表里有没有本程序；
3. 检查杀毒软件有没有拦截开机启动项。

**怎么解决**

- 在托盘菜单里把「开机自启」**关掉再打开**一次，重新写一次启动项；
- 如果在任务管理器的启动列表里被禁用了，把它**启用**；
- 尽量把 exe 放在**不经常移动的固定目录**（例如 `C:\Tools\MyopicDefocus\`），换目录后需要重新开关一次「开机自启」。

### 2.15 改了参数但看起来没反应

**现象**：在面板里改了滑块，画面没变化；或者退出重开后又变回去了。

**可能原因**

| 原因 | 说明 |
|------|------|
| 改的是**另一块屏** | 在「单独改这块屏」模式下改错了目标 |
| 被**暂停**了 | 参数改了但滤镜没在跑 |
| 参数算出来接近 0 | 见 [2.5](#25-画面完全没有模糊效果) |
| 配置文件没写成功 | 配置目录不可写（例如放在受保护位置） |

**怎么排查**

1. 确认滤镜处于**生效**状态（托盘菜单第一项显示「暂停效果」）；
2. 确认模式是「一套通用参数」还是「单独改这块屏」，以及选中的显示器对不对；
3. 把「效果强度」临时拉到最大（1.0）验证是否**有任何**变化 —— 这是最快的分界点；
4. 打开 `%APPDATA%\MyopicDefocus\config.json`，看看刚才改的数值**有没有写进去**。

**怎么解决**

- 模式/目标屏选错 → 重新选；
- 被暂停 → 从托盘菜单恢复；
- 数值没写进文件 → 检查配置目录权限；也可以删掉 `config.json` 让程序用默认值重建；
- 物理量填错导致 σ≈0 → 回看 [2.5](#25-画面完全没有模糊效果)。

### 2.16 用着不舒服眼睛累或头晕

**现象**：用一段时间后眼胀、头晕、恶心、视物模糊。

**可能原因**

| 原因 | 处理 |
|------|------|
| 效果强度过高 | 调低到 0.15~0.25 |
| 长时间连续使用 | 每 30~40 分钟远眺 20 秒 |
| 观看距离偏小 | 改成真实距离（一般 40~70 cm） |
| 本身就有眼疾 | 停止使用，咨询眼科医生 |

**怎么解决**

1. **立即降低效果强度**，或直接从托盘菜单**暂停效果**；
2. 调整观看距离，让屏幕处在正确的位置（屏幕中心略低于视线水平）；
3. 养成定时远眺的习惯；
4. **症状持续或加重请就医**。本软件不构成医疗建议。

## 三、排查信息怎么收集

程序内部的错误信息（抓屏失败、D3D 初始化失败、交换链创建失败等）走的是 Windows **调试输出通道**（`OutputDebugString`），**不会弹窗打扰你**。

想看这些信息：

1. 下载并运行 **Sysinternals DebugView**；
2. 以管理员身份启动 DebugView；
3. 启用「Capture Win32 / Capture Global」；
4. 复现问题（例如退出再启动一次程序）；
5. DebugView 里过滤 `MyopicDefocus` 关键字，把相关行复制下来。

提交问题时请一并附上：

| 项目 | 怎么取 |
|------|--------|
| Windows 版本 | 设置 → 系统 → 系统信息 → 「操作系统」 |
| 显卡型号与驱动版本 | 设备管理器 → 显示适配器 |
| 显示器尺寸与分辨率 | 设置 → 系统 → 显示 |
| 是否开着 HDR | 设置 → 系统 → 显示 → HDR |
| 程序日志 | DebugView 抓 `MyopicDefocus` 关键字 |
| 复现步骤 | 哪一步之后出现、出现过几次 |
