# 光学原理 · 近视离焦护眼工具

> 这份文档写给「懂一点物理、但不想啃论文」的读者。
> 目标：看完能明白「为什么红通道不动、绿蓝要糊、0.32 从哪来」，并且能自己算一遍。

---

## 零、一句话总结

> 把屏幕画面拆成红/绿/蓝三层，**红色原样透传**，**绿色和蓝色各自做一次高斯模糊（蓝色糊得更狠）**，再按「效果强度」和原图混合。
> 边缘因此出现红蓝分离的彩边，眼睛得到「这个画面更远」的视觉线索，睫状肌少用力一点。

下面把这句话里的每一环拆开。

---

## 一、什么是「近视离焦」（myopic defocus）

先约定几个词：

| 词 | 意思 |
|----|------|
| **屈光度 / 焦度 (D)** | 光学系统的「聚光能力」，单位是屈光度 (diopter, 记作 D)。1 D = 1 米焦距。数值越大，聚光越强 |
| **离焦 (defocus)** | 焦点没落在该落的位置上。焦点落在视网膜**前面** → 离焦在视网膜后（欠矫）；落在**后面** → 离焦在视网膜前 |
| **近视离焦** | 一种**特定的离焦状态**：焦点落在视网膜**前方**一点点。这时眼睛会把这个画面判断成「比实际更远的东西」，睫状肌随之放松 |
| **调节 (accommodation)** | 睫状肌改变晶状体曲率，让不同距离的东西成像在视网膜上。盯近处时睫状肌收缩，一直绷着就累 |

**近视离焦怎么来的？**

近视眼看远处（无穷远）时，理论上应该聚焦在视网膜上。但人眼的视网膜上，**视杆细胞最密集的区域（中央凹）**和**视锥细胞采样最密的位置**并不完全重合，再加上视网膜上髓鞘分布不均，实际焦点会稍微偏到视网膜**后面**一点点，差大约 **+0.23 屈光度**。

这个 0.23 D 的「天然欠矫」就是近视离焦点。

**为什么近视离焦能放松眼睛？**

睫状肌是「对焦执行器」。当画面传递的信息暗示「这东西在远处」时，睫状肌倾向于放松（这是**近视防控**的核心机制之一）。而屏幕上放出的光的空间分布，恰恰可以携带这种「更远」的线索。

## 二、什么是纵向色差（LCA）

**LCA = Longitudinal Chromatic Aberration，纵向色差。**

眼睛的角膜和晶状体不是完美的透镜：**不同波长（颜色）的光，被折射的程度不一样**。

- 波长短的（蓝紫）折射率高 → 折射得更厉害 → 焦点更靠**前**
- 波长长的（红）折射率低 → 焦点更靠**后**

同一个物体，红绿蓝三层分别在**三个不同的距离**上成像。这就是纵向色差。

### 人眼天然 LCA 的数值

人眼的天然纵向色差（用屈光度表示焦点在纵向上的差异）是：

| 通道 | 天然 LCA | 含义 |
|------|---------|------|
| 红 | **-0.23 D** | 焦点比标准位置**更靠后** 0.23 D |
| 绿 | **+0.24 D** | 焦点比标准位置**更靠前** 0.24 D |
| 蓝 | **+1.10 D** | 焦点比标准位置**更靠前** 1.10 D |

> 这三个数是人群统计值，不是每个人都一样 —— 这是本方法存在误差的根源之一，见第九节。

## 三、关键巧合：近视离焦点恰好补偿红光

把前面两节拼起来看：

```
近视离焦点   sh = +0.23 D
天然红色 LCA = -0.23 D
```

**这两项大小相等、符号相反。** 近视离焦点 +0.23 D 恰好把红色的 -0.23 D 抵掉了。

于是，加上近视离焦之后，各通道**剩余**的纵向色差是：

| 通道 | 剩余 LCA | 状态 |
|------|---------|------|
| 红 | -0.23 + 0.23 = **0 D** | 焦点回到标准位置 → **不需要任何额外模糊** |
| 绿 | +0.24 + 0.23 = **+0.47 D** | 焦点偏前 → 需要糊 |
| 蓝 | +1.10 + 0.23 = **+1.33 D** | 焦点偏得更多 → 需要糊得更狠 |

**这就是「红通道直通、绿蓝通道分别模糊」的全部理由。**

它不是「设计师觉得红通道不该糊」，而是一个物理结论：**近视离焦点补的就是红色的那份色差，补完之后红色已经完全准了。**

## 四、从屈光度到弥散圆半径

现在开始算。记号：

| 符号 | 含义 | 单位 |
|------|------|------|
| $screen$ | 眼睛到屏幕的距离 | mm |
| $pupil$ | 瞳孔直径 | mm |
| $lca$ | 该通道剩余的纵向色差（离焦量） | D |
| $G$ | 等效焦距 | mm |
| $circ$ | 弥散圆半径 | mm |
| $mm\_per\_px$ | 屏幕上每像素对应多少毫米 | mm/px |
| $\sigma$ | 高斯模糊的标准差 | px |

### 第 1 步：眼睛的等效焦距

眼睛在「对准距离 $screen$ 的屏幕」这个状态下，等效焦距就是 $screen$，对应屈光度：

$$P_{eye} = \frac{1000}{screen} \quad (\mathrm{D})$$

（$screen$ 用 mm，$1000/screen$ 就是 m⁻¹ = D。）

加上离焦量 $lca$ 之后，总屈光度变成：

$$P' = \frac{1000}{screen} + lca$$

由薄透镜公式 $1/f = P$，得到等效焦距：

$$\boxed{G = \frac{1000}{\dfrac{1000}{screen} + lca}}$$

> 直观理解：离焦量 $lca$ 越大，等效焦距 $G$ 越小 —— 相当于把「看东西的距离」变近了。

### 第 2 步：弥散圆半径

焦点从 $screen$ 挪到了 $G$，这个**相对偏移量**是 $\dfrac{screen - G}{G}$。
弥散圆的大小随瞳孔直径线性放大：

$$\boxed{circ = pupil \times \frac{screen - G}{G}}$$

### 第 3 步：化简（这一步很有用）

把 $G$ 代进去：

$$\frac{screen - G}{G} = \frac{screen}{G} - 1 = screen \cdot \frac{\dfrac{1000}{screen} + lca}{1000} - 1 = \frac{lca \cdot screen}{1000}$$

所以整个模型塌缩成一个非常简单的乘积：

$$\boxed{circ = \frac{pupil \cdot lca \cdot screen}{1000}}$$

**这一步是理解所有调参行为的关键**：三个物理量各占一个因子，**都是线性的**。

- 观看距离翻倍 → 模糊量翻倍
- 瞳孔直径翻倍 → 模糊量翻倍
- 离焦量（色差）翻倍 → 模糊量翻倍

### 第 4 步：从毫米换算到像素

屏幕有物理尺寸（对角线英寸数）和分辨率，两者共同决定每像素多少毫米：

$$diag\_px = \sqrt{resX^2 + resY^2}$$

$$diag\_mm = diagInch \times 25.4$$

$$\boxed{mm\_per\_px = \frac{diag\_mm}{diag\_px}}$$

于是「几何上该糊多大（毫米）」换算成「该糊多少像素」：

$$\boxed{\sigma_{px} = \frac{circ}{mm\_per\_px} \times 0.32}$$

**注意那个 0.32** —— 见第六节。

### 完整公式（可直接照抄）

```
LCA_nat = { r: -0.23 D, g: +0.24 D, b: +1.10 D }
sh      = +0.23 D                      // 近视离焦点，恰好补偿红光

lca_r   = LCA_nat.r + sh = 0.00 D      // 红 → 直通
lca_g   = LCA_nat.g + sh = 0.47 D
lca_b   = LCA_nat.b + sh = 1.33 D

G_ch    = 1000 / (1000/screen_mm + lca_ch)
circ_ch = pupil_mm * (screen_mm - G_ch) / G_ch        // 不取绝对值
sigma_ch = circ_ch / mm_per_px * 0.32
```

## 五、为什么蓝通道比绿通道糊得更狠

代入化简式 $\sigma \propto lca$：

$$\frac{\sigma_{blue}}{\sigma_{green}} = \frac{1.33}{0.47} = 2.8298$$

**这是一个常数。** 无论屏幕多大、坐多远、瞳孔多大，**蓝色的模糊量永远是绿色的 2.83 倍**。

原因很直白：蓝光的天然纵向色差（1.10 D）本来就比绿光（0.24 D）大四倍多，加上同样的 +0.23 D 离焦补偿后，两者的差距按比例保留。

而红通道的 $lca = 0$，代入化简式立刻得到 $circ = 0$、$\sigma = 0$ —— **这就是红通道直通的数学表达**，不需要额外写任何特判。

### 一个容易被误解的点：负值不取绝对值

上游公式写作 `circ = pupil * (screen - G) / G`，**没有任何 `abs()`**。这是硬性约定，**实现里不得改成取绝对值**。

- 对本项目实际使用的绿、蓝两个通道（$lca > 0$）和正的距离，$circ$ 恒为正（从化简式 $circ = pupil \cdot lca \cdot screen/1000$ 一眼可见）；
- 但符号约定本身有物理含义：**$circ$ 的正负代表焦点偏前还是偏后**。如果将来把某通道的 $lca$ 设成负值（例如直接使用未补偿的自然红色分量 -0.23 D），$circ$ 会变负；此时偷偷取绝对值会把「焦点偏后」这个物理含义悄悄翻转成「偏前」，模拟就变成了近视而不是远视。

保留符号，是为了让模型在参数域的任何位置都保持物理含义正确。

## 六、0.32 是什么

**0.32 是一个经验标定系数，不是推导出来的物理常数。**

它在公式里的位置是最后一步：

$$\sigma_{px} = \frac{circ}{mm\_per\_px} \times \underbrace{0.32}_{\text{标定系数}}$$

### 它在干什么

前面几步算出来的是「**几何意义上的弥散圆半径**（毫米）」。而真正要在屏幕上做的模糊是**高斯模糊**，高斯模糊的标准差 σ（像素）和几何弥散圆半径不是一回事。

一个粗略的对照：如果弥散是「半径 r 的均匀圆盘」，那么与它方差等效的最佳高斯核标准差是 $\sigma = r/2 = 0.5r$。上游取的是 **0.32**，比 0.5 更小 —— 也就是**视觉上比「几何等效」还要弱一档**。

这就是为什么必须做标定：像素级的观感（边缘有多糊、彩边多明显）很难靠纸面推导对上，只能靠实测调一个系数。

### 它的来历

- 浏览器扩展版（上游算法源头）在初始化时写死了这个数；
- 本项目 1:1 沿用它，**不做任何"优化"**；
- 它是一个**魔数**：换掉它，整个视觉效果都会变，而光学模型的其他部分（色差、离焦点、屈光度算式）都有物理依据。

**结论**：0.32 属于「视觉标定参数」，不是「物理参数」。改它需要重新做视觉评估，而不是重新做物理推导。

## 七、各参数怎么影响视觉效果

先固定一个基准：**24 英寸 / 1920×1080 / 观看距离 40 cm / 瞳孔 6500 μm**。

算出来的中间量：

| 量 | 值 |
|----|-----|
| $diag\_px = \sqrt{1920^2 + 1080^2}$ | 2202.9072 px |
| $diag\_mm = 24 \times 25.4$ | 609.6 mm |
| $mm\_per\_px$ | 0.276725 mm/px |
| $screen$ | 400 mm |
| $pupil$ | 6.5 mm |

蓝通道（$lca = 1.33$ D）：

| 量 | 值 |
|----|-----|
| $G_{blue} = 1000/(2.5 + 1.33)$ | 261.0966 mm |
| $circ_{blue} = 6.5 \times (400 - 261.0966)/261.0966$ | 3.458000 mm |
| 未标定像素量 $circ / mm\_per\_px$ | 12.496150 px |
| **$\sigma_{blue}$** | **3.998768 px** |

绿通道（$lca = 0.47$ D）：

| 量 | 值 |
|----|-----|
| $G_{green} = 1000/(2.5 + 0.47)$ | 336.7003 mm |
| $circ_{green} = 6.5 \times (400 - 336.7003)/336.7003$ | 1.222000 mm |
| 未标定像素量 | 4.415933 px |
| **$\sigma_{green}$** | **1.413098 px** |

高斯核范围：$\max(8,\ \lfloor 3.9988 \times 1.7 \rfloor) = \max(8, 6) = 8$，即每方向 17 个采样点。

## 八、渲染管线：怎么把公式落到 GPU 上

### 整体流程

```
屏幕
  │  ① DXGI Desktop Duplication 抓取
  ▼
原始纹理 (格式跟随源，8bit / 10bit)
  │
  │  ② Pass 1：水平方向可分离高斯
  ▼
中间纹理
  │
  │  ③ Pass 2：垂直方向可分离高斯 + 与原图按强度混合
  ▼
输出纹理
  │
  │  ④ 送到 Win32 分层窗口（鼠标穿透）
  ▼
屏幕
```

### ① 抓屏

用 DXGI Desktop Duplication API 把桌面画面抓进一张 D3D11 纹理。纹理格式**跟随系统给的源格式**，不硬编码。

### ② / ③ 两 pass 可分离高斯

高斯模糊在数学上可分离：

$$\text{Gaussian}_{2D}(x,y) = G(x) \cdot G(y)$$

所以「二维模糊」可以拆成「水平模糊 + 垂直模糊」两趟，代价从 $O(n^2)$ 降到 $O(n)$。

**核的构造：**

| 项 | 取值 |
|----|------|
| 采样范围 | $\text{range} = \max\left(8,\ \left\lfloor \max(\sigma_b, \sigma_g) \times 1.7 \right\rfloor\right)$ |
| 权重 | $w(i) = \exp\left(-\dfrac{i^2}{2\sigma^2}\right)$ |
| 归一化 | 每个通道**各自**除以自己的权重和 |

> **1.7 倍的范围**：高斯函数在 ±1.7σ 处大约还剩 91% 的能量。再往外截断损失很小，但采样数少一半性能就好很多 —— 这是画质/性能的标准取舍。
> **下限 8**：极小的 σ 时代码要采样至少 ±8 个点，避免出现「数学上该有模糊、实际却只有一个像素有效」的退化情况。

**通道分离（着色器里的关键几行）：**

```hlsl
// 每次采样同时累加两个通道，用各自的 σ 算权重
float wB = Gaussian((float)i, blurB);   // 蓝通道权重
float wG = Gaussian((float)i, blurG);   // 绿通道权重
sum.b += col.b * wB;   totalW.x += wB;
sum.g += col.g * wG;   totalW.y += wG;

// 红通道：不参与卷积，直接取原样
blurred.r = currentSample.r;

// 逐通道独立归一化
blurred.g = (totalW.y > 0) ? sum.g / totalW.y : currentSample.g;
blurred.b = (totalW.x > 0) ? sum.b / totalW.x : currentSample.b;
```

**强度混合（第二趟末尾）：**

```hlsl
// 第二趟：从原始纹理取原图，按 strength 与模糊结果插值
float3 realOriginal = texOriginal.SampleLevel(sam, input.uv, 0).rgb;
return float4(lerp(realOriginal, blurred, strength), 1.0);
```

`strength = 0` 就是原图，`strength = 1` 就是纯模糊版。默认 0.25。

### ④ 输出

送进一个 Win32 **分层窗口**：

```
WS_EX_TOPMOST | WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE
```

| 标志 | 作用 |
|------|------|
| `TOPMOST` | 永远在最上层 |
| `LAYERED` | 分层窗口（可以按像素合成） |
| `TRANSPARENT` | **鼠标点击穿透** —— 滤镜不挡操作 |
| `TOOLWINDOW` | 不在任务栏显示 |
| `NOACTIVATE` | 不抢焦点、不打断你正在输入的窗口 |

### 和浏览器扩展版（SVG filter）的对应关系

上游浏览器扩展用的是 SVG 滤镜，本项目用 GPU 着色器，两者是**等价的实现**：

| 浏览器扩展（SVG filter） | 本项目（GPU 着色器） |
|------------------------|-------------------|
| 3 个 `feColorMatrix` 拆出 R/G/B | 着色器里按通道分别加权累加 |
| 2 个 `feGaussianBlur`（`stdDeviation` = σ） | 两 pass 可分离高斯 |
| `feComposite operator="arithmetic" k2=1 k3=1` 把通道加回来 | 输出合并三通道 |
| `feComposite k2=(1-strength) k3=strength` 与原图混合 | `lerp(original, blurred, strength)` |
| `backdrop-filter: url(#...)` 作用在页面上 | 分层窗口覆盖整个桌面 |

## 九、这个模型没有覆盖什么

诚实地列一下：

| 忽略了什么 | 后果 |
|-----------|------|
| **眼睛的轴长（约 24 mm）** | 模型里的几何部分没有显式出现视网膜位置，实际是折叠进 0.32 这个标定系数里 |
| **个体差异** | 每个人的瞳孔大小、轴长、角膜曲率、调节幅度都不同，LCA 的三个常数（-0.23 / +0.24 / +1.10 D）是人群统计值 |
| **周边视觉与对比敏感度** | 真实视网膜周边的视觉特性与中心不同，屏幕端无法复现 |
| **双眼辐辏与立体视觉** | 「屏幕变远」是通过色差间接产生的**弱深度线索**，不是真正的立体深度 |
| **HDR / 广色域** | 本软件不做 HDR 适配 |
| **屏幕本身的色彩管理 / 伽马** | 显示器 OSD 的设置会改变实际观感 |

---

## 十、结论：这个工具到底在做什么

1. 它**没有改变你眼睛的屈光状态**，近视不会因此逆转；
2. 它做的是**屏幕端的光学模拟**：把画面按物理上应有的纵向色差重新分配，让颜色分离，从而给眼睛一个「更远」的弱深度线索；
3. 其中「红色直通、绿蓝各糊、蓝色糊 2.83 倍」这些细节**不是审美选择，是物理结论**；
4. 唯一带「魔数」性质的是 0.32 标定系数，它是视觉调出来的，不是推导出来的；
5. 个体差异是这套方法的**主要误差来源** —— 所以它应该被当作「减小睫状肌负担」的辅助工具，而不是精确的医疗手段。

**再次声明**：本软件仅供学习与实验，不构成医疗建议。使用中出现头晕、恶心等眼部不适，请立即停止使用。
